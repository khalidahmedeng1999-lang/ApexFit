## Project Overview

**ApexFit EG** is an offline-first Android workout tracker and hybrid athlete fitness app. All source is currently packaged in `apexfit-eg (3).zip` — extract it before making changes:

```bash
unzip "apexfit-eg (3).zip" -d .
```

Built with Kotlin, Jetpack Compose, Material Design 3, Room Database, and optional Gemini AI.

## Build Commands

```bash
# Debug APK → app/build/outputs/apk/debug/app-debug.apk
./gradlew assembleDebug

# Release APK (requires signing env vars; see Secrets below)
./gradlew assembleRelease

# Run all JVM tests (Robolectric + Roborazzi)
./gradlew test

# Run a single test class
./gradlew test --tests "com.example.ExampleUnitTest"

# Instrumented tests (requires connected device or emulator)
./gradlew connectedAndroidTest

# Lint
./gradlew lint
```

## Secrets & Environment

API keys are injected via the **Secrets Gradle Plugin** (`secrets-gradle-plugin`), which reads from `.env` (not committed) and falls back to `.env.example`.

```
# .env (create locally, never commit)
GEMINI_API_KEY=your_key_here
```

Release signing reads from env vars: `KEYSTORE_PATH`, `STORE_PASSWORD`, `KEY_PASSWORD`. Both debug and release builds currently use `debug.keystore` with the standard Android debug credentials.

## Architecture

Single-activity MVVM with no DI framework — dependency wiring is manual via `ViewModelFactory`.

### Data Flow

```
Room DB (AppDatabase)
    └── WorkoutDao (single DAO for all 11 entities)
            └── WorkoutRepository (single repo; all business logic lives here)
                    └── WorkoutViewModel (single ViewModel for all state)
                            └── UI Screens (Compose, 6 bottom-nav tabs)
```

- **`WorkoutViewModel`** holds one `WorkoutUiState` (a large data class) exposed as `StateFlow`. All screen state — programs, logs, active workout session, rest timer, food diary, nutrition summary, weight logs — lives here.
- **`WorkoutRepository`** wraps Room flows and the two network services. It also seeds the default "ApexFit Hybrid Athlete" 14-day preset via `seedApexFitHybridAthleteProgram()`.
- **`AppDatabase`** uses `fallbackToDestructiveMigration()` — incrementing `version` in `AppDatabase.kt` **wipes all user data**. Write a proper migration or bump version only intentionally.

### Bottom Navigation Tabs

`BottomTab` enum in `BottomNavBar.kt`: **Dashboard → Workout → Nutrition → Volume → History → Profile**. Navigation state is a `selectedTab` variable in `MainActivity`; there is no Jetpack Navigation Graph.

### Food Search (4-Layer Cascade)

`WorkoutRepository.performMultiLayerFoodSearch()` tries layers in order:
1. Local `FoodItem` Room table (exact + fuzzy match)
2. USDA FoodData Central REST API (`UsdaFoodApiService`) — uses `DEMO_KEY` by default; replace for production
3. Built-in Egyptian & global food knowledge base (hardcoded map in `AiFoodSearchService`)
4. Gemini AI live call via `AiFoodSearchService.generateAiEstimate()` — only fires if `GEMINI_API_KEY` is set

### Key Entities

- **Program → WorkoutDay → ProgramExercise**: the workout plan definition (templates)
- **WorkoutLog → LoggedExercise → LoggedSet**: immutable training history
- **UserProfile** (single row, `id = 1`): drives TDEE/macro calculations in `NutritionCalculator`
- **FoodItem**: shared catalog used by both the search cache and food diary
- **FoodLog**: dated diary entries referencing a `FoodItem` by `foodId`

### Active Session State

An in-progress workout exists only in memory inside `WorkoutViewModel.activeSession: ActiveTrainingSession`. It is not persisted until `finishWorkout()` is called, which writes to Room. A process kill loses an in-progress session.

## Testing Notes

- Roborazzi screenshot tests run on JVM via Robolectric — no device needed.
- `testOptions { unitTests { isIncludeAndroidResources = true } }` is set so resource lookups work in JVM tests.
- Screenshot golden images are generated by Roborazzi; update them with `./gradlew recordRoborazziDebug` if UI changes.
